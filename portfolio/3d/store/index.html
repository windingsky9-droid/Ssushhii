Change anything in the configurator and this panel fills in — it is listening, not polling.
1

The configurator runs in an iframe and posts its configuration to this page on every change. This page never reads inside the frame — it only receives messages, and it checks where they came from.

What this demo is showing. The build code in the cart line is the same string the configurator displays, and the same string in its URL — so a customer quoting a code, sending a link, or placing an order all give you one identifier. Reopen this configuration on a cart line restores the exact build.

What a real store would do differently. This page trusts the price in the message because it is a demo. A real store must not: the price is computed in the browser and anyone can edit it in devtools. Charge from a real variant or a server-side price rule, and carry the build code as a line-item property. The bundled examples/shopify-liquid.txt says the same thing and shows the Liquid.
