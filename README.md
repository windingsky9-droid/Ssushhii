# Sushir 3D Studio

Real-time 3D in the browser, written by hand. No three.js, no build step, no
framework — the renderer is a single HTML file that runs on the visitor's GPU.

## What is in here

**`portfolio/3d/`** — a product configurator. Five products, every one drawn by
the same hand-written WebGL2 renderer: colour, finish, hardware and lighting
re-shaded in real time. It posts the customer's exact build to a parent page,
so a store can write it straight into a cart.

**`portfolio/renders/`** — 600 studio renders at 2000×2000, generated by
pointing the configurator at itself offscreen. Five products, six colourways
each, five lighting setups, four camera angles. Ten are free at full
resolution with no email gate.

**`portfolio/demos/astral-vault.html`** — a natal chart that actually computes.
Planetary positions from Keplerian elements plus a truncated lunar series,
bodies lit from the true solar direction so the phases are real, and geocentric
traces whose loops are genuine retrograde motion. Verified against known
constants before it shipped: the Sun lands 0.08° from its J2000 value, every
sidereal period within 0.031%, the Moon's synodic month within five minutes
over 101 cycles.

**Market Observatory** (`app.py`, `src/`) — a Flask research dashboard with a
clean provider boundary, deterministic demo mode, and server-side credentials.
Its own section is below.

## Tooling

`tools/render-farm/` drives the configurator offscreen and writes one PNG per
configuration, then builds the gallery page and the free sample from the
resulting manifests. Every number on the public gallery is derived from
`manifest.csv` rather than typed, because it shipped once reading "384 renders,
4 products" after a fifth product had been added.

## Tests

```sh
python -m pytest -q
```

`tests/test_portfolio_pages.py` is worth singling out: each assertion in it is a
bug that actually reached production — a nested `<a>` that dropped the work grid
on top of the hero, a 4.2 MB hero hotlinked from raw.githubusercontent.com,
copy claiming four products above a five-product picker, and a generated page
edited by hand until it disagreed with its own manifest. Each guard was checked
by reintroducing its bug and watching it fail.

# Market Observatory

A zero-required-cost market research MVP built around a clean provider
boundary. It runs immediately with deterministic demo data and switches to
server-side Factor Weave research when `FACTORWEAVE_API_KEY` is configured.
It is a research product, not an auto-trader and not a promise of investment
returns.

## Run locally — $0 path

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Open `http://127.0.0.1:5000`. The app automatically loads a SPY demo snapshot.

## Optional live Factor Weave mode

1. Copy `.env.example` to `.env`.
2. Put a Factor Weave API key in `FACTORWEAVE_API_KEY`.
3. Load that environment before starting the app.
4. Keep `.env` local; it is ignored by Git.

The browser never receives the Factor Weave credential. Provider requests are made by Flask on the server.

## Optional payments

Create hosted Stripe Payment Links only when you intentionally want to accept payments, then set `STRIPE_PRO_URL` and/or `STRIPE_CREATOR_URL`. Until those variables are present, the paid buttons remain disabled. This MVP does not collect card data or require a Stripe secret key.

See [`docs/REVENUE_SETUP.md`](docs/REVENUE_SETUP.md) for the end-to-end proof, live-provider, checkout, and first-revenue flow. `.env.example` documents the supported local variables; real credentials stay in `.env` or the deployment host's secret manager.

## Test and verify

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m compileall app.py src
```

## Hosted deployment

The repository includes a generic production entry point (`wsgi.py`), a `Procfile`, and a Dockerfile. Hosts that support Procfiles can use:

```text
gunicorn --bind 0.0.0.0:$PORT --workers 2 --threads 4 --timeout 60 wsgi:app
```

For Docker-based hosting:

```powershell
docker build -t market-observatory .
docker run --rm -p 5000:5000 --env-file .env market-observatory
```

Keep `FACTORWEAVE_API_KEY`, `STRIPE_PRO_URL`, and `STRIPE_CREATOR_URL` in the host's secret/environment settings. Never bake `.env` into an image or commit it.
